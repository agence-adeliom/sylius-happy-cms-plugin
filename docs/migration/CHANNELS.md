# Channels update note

`Menu`, `SharedBlock` and `Config` can now be attached to Sylius channels, and a configuration value can be overridden per channel
(see [channels](../channels.md)).

## What to do

1. Run the migrations: the plugin ships `Version20261029000001` (three join tables) and `Version20261029000002`
   (`channel_values` JSON column on the config translation table). They only add tables and a nullable column, no existing data is modified.
2. Clear the cache.

Without any setting, the behavior is **identical to before**: an empty `channels` relation means "all channels".

## Custom table names

The shipped migrations target the standard names generated by `make:happy-cms:install`: `sylius_happy_cms__menu`,
`sylius_happy_cms__shared_block`, `sylius_happy_cms__config` and `sylius_happy_cms__config_translation`, on MySQL.
If your project uses other table names, or another database platform, generate your own migration instead:

```bash
php bin/console doctrine:migrations:diff
```

The join tables keep the fixed names `sylius_happy_cms__menu_channels`, `sylius_happy_cms__shared_block_channels` and
`sylius_happy_cms__config_channels`.

## Notes for projects that override plugin classes

- `ConfigTranslationInterface` gets `getChannelValues()`, `setChannelValues()`, `getChannelValue()` and `setChannelValue()`.
  A project that implements it without extending the plugin `ConfigTranslation` must add them.
- `ConfigRepositoryInterface` declares `getByKey()` (already implemented by `ConfigRepository`).
- `MenuInterface`, `SharedBlockInterface` and `ConfigInterface` are unchanged: the channels API is in the separate `ChannelAwareInterface`.
